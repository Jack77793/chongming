# 虚拟场景需求与第一版实现边界

本文把虚拟场景的需求分析整理成可实现、可验收的第一版规格。它补充 [`代码框架.md`](代码框架.md)，不改变项目主规范 [`instruction.md`](../instruction.md) 的范围。

## 1. 目标与出口

虚拟场景每次运行都从一份可持久化的 `ScenarioSpec` 和一个明确的随机种子启动。场景驱动一条实验时钟，按曝光和采样计划产生三个逻辑出口：

1. **视频出口**：按站点、相机角色和图像会话输出 `CameraFrame`。主相机和辅助相机是两条独立采样流，某一时刻未采样的角色为 `None`。视频出口不含真实目标 ID、跨站对应关系或其他真值答案。
2. **伪装发包出口**：按站点和虚拟会话输出普通校准状态、射线和诊断事件。射线只携带设备端在该场景中“能够得到”的字段，不携带 `TruthObjectId` 或正确跨站对应关系。
3. **真值出口**：输出受保护的 `ScenarioTruth`，包括实际相机状态、目标状态、可见性、有限视线段、遮挡原因、环境采样和视频/事件之间的评估对应关系。真值只交给评估、监视和证据写入端口。

三个出口在一个 `ScenarioStep` 中按同一实验时刻同步描述，消费者可以分别订阅，但不得共享可变对象。编排层必须把视频送往设备端、普通事件送往传输/中心、真值送往评估/监视；真值不能因为方便而混入在线数据结构。

## 2. 可复现和可持久化

场景配置、站点配置、相机元数据、飞行器元数据、环境配置、时间线、随机种子、配置版本和外部素材摘要必须进入运行 manifest。配置中的二进制参考图像、网格或纹理使用外部 URI 与 digest，不能把不可序列化的 ndarray、打开的文件或 Python callable 放进 `ScenarioSpec`。

同一份配置、同一随机种子、同一代码和依赖版本应产生相同的时间戳、相机状态、目标状态、可见性、真值射线和普通虚拟事件内容；每次运行新建的会话 ID 可以不同。所有随机性必须来自显式的、按对象和模块划分的 deterministic stream，禁止读取 wall clock、全局随机状态或未声明的 RNG。

飞行器的“行为代码”通过稳定的 `behavior_id`、实现版本、参数和随机流名称引用，由运行时 registry 解析。持久化配置不保存函数对象；第一版优先使用确定性的轨迹或行为实现。

## 3. 第一版场景组成

### 3.1 世界、地形和地物

- 世界使用已有 ENU 坐标和明确的 `GeodeticAnchor`。
- 地形支持平面和有限起伏的 heightfield/三角网格两种第一版表示。地形有稳定 ID、基础高程、几何或外部资源引用、材质和是否参与遮挡的声明。
- 地物指建筑物、杆塔、基础设施和固定参照等不主动运动的物体。每个地物有稳定 ID、显示名、类别、几何、姿态、材质和 `occludes_sight_lines`。
- 第一版的目标捕获条件是：目标中心参考点在相机视场内，并且从光学中心到该点的有限闭合线段没有被参与遮挡的实体阻断。目标后方的物体不产生遮挡，目标自身表面接触不算外部遮挡。

### 3.2 边缘设备和相机

每个边缘设备有稳定的 `station_id`、显示名和硬件/安装元数据，并至少包含一台主相机和一台辅助相机。相机元数据与在线 `StationConfig` 分开保存；场景实际生成参数不能从带误差的在线估计反推。

第一版基线 profile 为：

| 相机 | 分辨率 | 帧率 | 对角线视场 | 安装约束 |
| --- | --- | --- | --- | --- |
| 主相机 | 1920×1080 | 30 fps | 约 60° | 姿态由场景实际相机轨迹直接给出 |
| 辅助相机 | 640×480 | 30 fps | 约 20° | 相对当地水平参考系的 pitch、roll 为 0；yaw 和光心平移可配置 |

分辨率、帧率和 FOV 在数据结构中仍显式保存，以便未来做 profile 覆盖。第一版配置校验应拒绝违反基线 profile 的场景，除非场景明确声明使用实验 profile。实际投影以 `fx/fy/cx/cy` 为准，FOV 只是可审计的名义元数据；“1/4 英寸传感器”和“3 mm 镜头”作为描述字段，不直接替代真实内参计算。

监视器根据实际光学姿态和投影参数推导视锥体，用四棱锥显示设备 ID、相机角色和 FOV。视锥体是显示结果，不应在在线事件中增加一份独立的几何真值。

### 3.3 飞行器

飞行器可以是球、盒或简单网格，至少有稳定的 `TruthObjectId`、显示名、型号/类别、几何、外观和机体参考点。真值快照必须给出位置、速度和姿态，因此监视器能够显示速度矢量。

飞行器支持单个或多个实例。每个实例使用确定性 `FlightBehaviorSpec` 或确定性轨迹；行为实现只能依赖实验时刻、显式参数和受控随机流。第一版可先实现 HOLD、LINEAR 和预生成 knot 轨迹，再通过 registry 扩展行为代码。

当目标在主相机视场内且有限视线段无遮挡时，真值出口产生一条从主相机光学中心指向目标中心参考点的单位 ENU 射线。普通伪装包可以有一条对应的 `RayEvent`，但只使用在线会拥有的会话、序号、校准引用和不确定度字段；真实目标 ID 和跨站关联只出现在真值出口。

## 4. 环境与成像质量

环境效应分为“改变可见性/遮挡的世界状态”和“降低成像质量但不改变几何可见性的成像状态”。二者不能用一个布尔值混在一起。

### 第一版必须可配置但可以关闭

- 太阳方向、天空颜色和基础照度。
- 基础线性颜色空间、传感器噪声范围、强度裁剪和曝光采样数。
- 无植被、无雨、无雾、无云、无高频抖动的清洁基线。

### 后续扩展点

- **太阳和廉价传感器**：自动曝光、有限动态范围、饱和、炫光和光晕。应输出评估用的饱和/炫光/曝光真值，不把后处理标签送到在线算法。
- **大气**：Rayleigh 散射、大气透视、距离相关的对比度衰减、雾和雨。雾通常降低成像质量；云只有在明确配置为遮挡体时才进入有限线段遮挡判断。
- **植被和风**：植被作为独立的动态世界对象，有确定性基础姿态和受风场驱动的采样状态；不能只在静态地物上附加一个未使用的扰动字段。
- **云层**：可分别表达能见度衰减和实体遮挡，不能默认两者等价。
- **相机抖动**：区分真实光学姿态扰动（影响真值相机状态和射线）与像素/亚像素级成像模糊（只影响视频和成像质量真值）。高频抖动必须有确定性时间模型。

这些扩展先进入配置、端口和真值字段，不阻塞平面/晴空/无抖动的基础场景。每加入一种效应，都要保留可关闭的对照模式。

## 5. 第一版接口拆分

场景代码按以下顺序实现：

1. `ExperimentClock`：初始化并推进唯一实验时钟；监视刷新和渲染线程不能推进时间。
2. `TrajectorySampler` / 行为 registry：在曝光时刻采样相机和飞行器状态。
3. `CameraProjector`：使用实际内参、畸变和光学姿态计算投影、FOV 和目标像素尺寸。
4. `VisibilityResolver`：对静态地物和启用的动态遮挡体执行有限线段查询，并保留 blocker ID 与相交位置。
5. `SceneLogic`：组合世界、相机、目标、环境和可见性为不可变快照。
6. `CameraImager`：按主/辅独立采样计划生成原始 `ImagePlane`，不重新决定几何可见性、不访问在线算法。
7. `VirtualObservationGenerator`：从真值帧和在线配置生成普通校准/射线/诊断事件及独立虚拟会话序号。
8. `ScenarioSource`：把视频、普通事件和真值按实验时刻组装成三个出口。

## 6. 第一版验收场景

以下验收不要求具体检测算法，但要求场景输出正确且可审计：

- 同一配置、种子、代码版本重复运行，除新会话 ID 外输出逐项一致。
- 0/1/N 个飞行器、1/2/N 个站点均能装配；0 飞行器时视频和进度仍正常，普通事件为空。
- 平坦地形、有限起伏地形、静态建筑/基础设施可配置；视线被挡时记录 blocker，目标出视场或被挡时不产生真值射线。
- 主辅相机独立采样，涵盖只采主帧、只采辅助帧和同一时刻同时采样；每帧的站点、角色、会话和曝光时间一致。
- 对一个曝光时刻和 N 个无遮挡站点，虚拟包最多产生 N 条普通射线；跨站目标对应只在真值出口。
- 普通在线输出递归检查不到 `TruthObjectId`、真值对应表、真实相机姿态或扰动参数。
- 目标状态按曝光中点采样；场景时钟不受 wall clock、监视刷新或渲染调用改变。

## 7. 当前采用的实现假设

- `display_name` 属于真值/监视元数据，不进入 `RayEvent`。
- 辅助相机 pitch、roll 的零点参考当地 ENU 水平坐标系；yaw 可配置，光心相对主相机的平移保留在实际姿态与安装配置中。
- 第一版成像器使用统一线性灰度 `gray8` 输出，先验证时钟、投影、遮挡和数据流；物理级炫光、自动曝光、彩色成像和复杂天气按扩展实现。
- “伪装视频”和“伪装发包”描述的是对后续模块可见的普通在线输出，不要求第一版立即确定网络协议或文件封装格式。

## 8. 已确认的第一版决定

以下决定已经确认，后续实现应把它们视为默认约束：

1. 主/辅相机采用本文件中的基线 profile；场景只有在显式声明实验 profile 时才能覆盖分辨率、帧率或 FOV，并且覆盖值进入 manifest。
2. 第一版图像输出采用灰度字节格式（`gray8`）；`ImagingSpec.color_space` 仍声明为线性空间，后续可以在不改变帧契约的情况下增加彩色 profile。
3. 飞行器行为只通过仓库内预注册的稳定 `behavior_id` 和实现版本选择。配置不允许动态导入任意 Python 路径；行为参数和命名随机流必须可持久化且可复现。

这三项决定与严格窗口封存策略一起，构成第一版实现的固定边界。内部成像和虚拟观测接口也将把普通结果与真值结果分成不同类型，避免真值沿在线数据流传播。
