# 虚拟场景视频预览

本轮提供可独立启动的虚拟场景子系统。它复用场景时钟、逻辑快照、投影、遮挡与成像接口，输出由 Apple Metal GPU 生成的真实几何 RGB8 视频，并生成普通虚拟校准状态、世界射线和独立真值对应；完整设备检测、真实标定和中心融合运行链路仍在后续开发范围。

## 启动

在仓库根目录执行：

```sh
uv sync
uv run chongming-preview
```

也可以执行 `uv run python -m chongming`。默认启动本地服务并自动打开浏览器，地址为 <http://127.0.0.1:8765/>。终端按 Ctrl+C 停止。

```sh
# 不自动打开浏览器，改用 8766 端口
uv run chongming-preview --no-browser --port 8766

# 实验仍按相机采样计划推进，预览生产限制为每秒 8 个离散 tick
uv run chongming-preview --render-fps 8

# 两站预览；支持 1–4 个站点
uv run chongming-preview --stations 2

# 从可编辑 authoring JSON 场景启动；外部素材相对 JSON 文件目录解析并校验 SHA-256
uv run chongming-preview --scenario scenarios/review.json
```

默认使用规定的标准相机输出：主相机 1920×1080、辅助相机 640×480、RGB8、主/辅对角线 FOV 分别为 60°/20°，辅助相机保持水平安装。`--fps 1` 至 `--fps 60` 只调整实验采样周期，不改变图像分辨率；默认 30 fps。

运行要求 macOS、可用的 Apple Metal GPU 和 Swift 编译器（Xcode Command Line Tools）。首次启动会在 `.codex-cache/` 编译原生进程；该目录是本地构建缓存。

像素生成使用持久化 Swift/Metal 子进程的 compute shader；Python 负责逻辑真值、场景序列化、RGB8 回读及传感器后处理。没有 Metal 时启动会明确失败，不会退回 CPU 像素渲染。GPU buffer 按容量复用，请求串行处理，直接回传紧密 RGB8，避免 RGBA 拆通道和重复整帧复制。正常 Ctrl+C 会先停止生产线程，再通过 stdin EOF 关闭原生进程、释放管道。

浏览器 Canvas 显示已经生成的视频和场景监视视图。预览采用无损 PNG，原始 `CameraFrame` 为 `rgb8`。像素提交按每台相机独立的曝光计数选择，逻辑/事件/真值采样仍覆盖所有步骤。PNG/Base64 只按查看请求编码选中站点的主辅两路，编码不在模拟生产线程执行。没有查看者时不编码，暂停时复用缓存，同一序号不重复传输图像。每个相机角色只保留最近一帧及其匹配的叠加真值，预览缓存不积累历史帧。

采样时间由实验时钟确定。机器算不过来时播放变慢，不丢弃逻辑/事件采样，也不改写帧时间戳。页面允许跳过已经过时的显示快照；请求之间至少间隔 60 ms，预览显示率不等于原始采样率。预览生产另有独立的离散渲染时钟：默认 10 Hz，可用 `--render-fps` 调整。当前调度按曝光周期推导的最高采样率计算 `render_every`，各相机独立每隔该数量的曝光提交一次像素，不因主辅起始时刻不同产生饥饿。所有步骤仍生成逻辑快照、普通虚拟事件和受保护真值；部分或全部跳过的 frame IDs 和 `render_skip_reason=discrete_render_clock` 显式记录，`rendered` 表示该组是否有任何像素提交。全跳过组的 GPU submission 和渲染耗时为零，不计为检测漏帧。全部逻辑步与实际渲染步分别统计尾部耗时。

场景 JSON 使用 `scenario-authoring-v2` 当前格式。它是面向人工维护的语义配置，不是 `ScenarioSpec` 的转储：用秒、米、轨迹行为和站点位置描述意图；加载时编译为内部运行模型，推导旋转矩阵、固定 FOV 的相机内参、参考地标和在线配置，再校验 RGB8、时间周期、行为 registry 和外部素材 digest。没有向前/向后兼容承诺。可用 `uv run python scripts/export_demo_scenario.py scenarios/local-review.json --stations 2 --duration 2` 生成短程模板，默认 30 fps。

可直接使用仓库中的 `scenarios/review.json`（两站、24 秒、四路有限流，37 行）。起伏地形、匀速交叉与空目标对照见 [测试场景说明](../scenarios/README.md)。常用编辑入口如下：

| 目标 | JSON 路径与约束 |
| --- | --- |
| 时长 | `duration_s`；正数，单位秒 |
| 随机性 | `random_seed`；整数，决定噪声和虚拟检出/误警 |
| 主辅采样 | `fps`；只改变实验曝光周期，输出分辨率固定为主 1920×1080、辅 640×480 |
| 站点 | `stations[].position_enu_m`；相机朝向、内参、配置和校准参考由编译器推导 |
| 目标数量/运动 | `targets`；当前支持 `orbit` 和 `constant_velocity`，不需要手写轨迹 knot |
| 起伏地形 | `terrain`；`heightfield` 类型、网格原点、正间距和矩形高度数组，详见场景说明 |

authoring 文件只保留场景参数；完整 compiled `ScenarioSpec` 仅作为证据目录中的诊断文件输出，不作为主编辑入口。行为通过仓库内 registry 选择，不允许动态导入 Python。当前参考来源支持测绘地物，内嵌参考图像未实现；起伏地形支持内联高度网格，外部地形素材仅有摘要校验、尚无解析器，天气等未实现效果运行前明确拒绝。

有限流验收使用独立 runner（默认不降速）：

```sh
uv run chongming-scene --scenario scenarios/review.json --output results/review-full
uv run chongming-scene --scenario scenarios/review.json --output results/review-reduced --render-every 3
```

输出包括 `authoring.json`、`manifest.json`、编译后的诊断 `scenario.json`、`online.jsonl`、`truth.jsonl`、`timing.jsonl`、`summary.json` 和 `video/camera-*/` PNG；目录必须事先不存在。普通事件与真值分开保存，图像算法评估必须使用 `--render-every 1`，不会为跳过帧伪造图像或检测结果。

## 本轮内容

三类对象都有具体实例：世界物体包含平面地形、建筑、球形地物和固定黑白参考面板；摄像机包含每站独立主辅相机；飞行物包含球、盒和简化飞机三角网格。飞行物沿确定性轨迹或注册行为运动，有限场景在预览中自动循环，有限 runner 则正常结束。

成像使用实际光学姿态和内参，在 GPU 上计算物体表面、轮廓、深度遮挡和基础彩色光照；Python 保留曝光多次采样、确定性传感器噪声与 RGB8 裁剪。飞行物中心不可捕获时，仍可能看到未遮挡的部分轮廓。主相机捕获状态按需求中的“中心在视场内且中心视线无遮挡”判定，不等同于任意像素可见。

页面提供播放/暂停、单步、回到起点、站点切换以及可旋转/缩放的场景总览。真值叠加默认关闭；打开后显示投影框与目标 ID，叠加只发生在预览画布，原始 `CameraFrame` 不含真值标签。场景总览显示摄像机视锥、目标速度、遮挡交点和选中站点发出的普通虚拟射线；顶部显示校准事件、射线和诊断数量。回到起点与自动循环均创建新图像/虚拟事件会话，暂停状态下回到起点会发布第一帧并继续暂停。

当前支持平面或内联高度网格地形、无畸变相机和清洁环境；高度网格用于成像、逻辑遮挡和总览，网格外仍为平面。普通虚拟发包已支持确定性检出/漏检/误警、校准有效区间、冻结、过期和无可信解诊断；射线携带独立误差、安装状态和校准解引用，真值对象 ID 与跨站对应只存在于受保护真值出口。大气透视、复杂天气/自动曝光和 GPU 镜头畸变尚未完成；非零畸变会明确报错。飞行物互遮挡尚未进入逻辑可见性，边界见测试场景说明。预览不代表这些原始需求已验收完成。旧需求文档中的首版 `gray8` 约定以用户最新的 RGB8 要求为准。

## 性能测量与 Web 判断

页面的“生成”是全部相机的场景逻辑、成像及监视元数据墙钟时间，不含 PNG；“PNG 编码”包含选中站点的两路 PNG/Base64。“GPU”使用 Metal command 的 GPU 时间；“其余成像”是成像模块墙钟时间减 GPU 时间，包含序列化、IPC、调度等待、回读、后处理及真值组装，不能解释为纯 CPU 执行时间或利用率。

浏览器的“请求”包含服务端编码、等待、传输和读取响应；“JSON 解析”只计 `JSON.parse`。“解码”计 data URL 设置和并行 `Image.decode()` 的墙钟时间；“绘制调用”计 Canvas 提交及视频 DOM 组装，未覆盖完整 GPU 合成和屏幕呈现。

2026-10-13 在 Apple M4 / 24 GB / macOS 26.6 上停止其他预览生产负载后，暖机 5 步、采样 30 步的同步基准结果如下（均为平均 ms；不含 HTTP 与浏览器）：

| 基准 | 原始帧生成 | GPU | 其余成像 | 场景逻辑/事件 | 监视元数据 | PNG/Base64 | JSON |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 站 / 查看该站 | 17.06 | 2.89 | 4.71 | 9.46 | 0.66 | 15.08 | 0.81 |
| 4 站 / 查看 1 站 | 63.78 | 15.35 | 15.98 | 32.45 | 1.85 | 12.97 | 1.55 |
| 4 站 / 对照编码全部站 | 61.58 | 14.43 | 15.64 | 31.51 | 1.94 | 49.63 | 2.39 |

这组数据只覆盖场景开头约一秒，不能代替完整轨迹和长时间性能验收，亦不作为不同运行条件下的严格提速比例。四站原始帧生成范围约 55–77 ms，尚未达到 30 fps 的 33.3 ms 预算。并行运行 CV 和中心算法的性能尚未验证。

浏览器实测中，旧版四站全部八路解码的 8 个样本约 13–17 ms；按需版两路解码样本约 4–7 ms，绘制调用约 0.2–0.8 ms。这些小样本不能代表最差延迟。服务端 PNG 和逻辑遮挡计算已显示明确开销，目前保留网页。只有在减少预览编码/传输、明确测出浏览器解码或完整呈现仍超预算后，再比较原生显示方案；不能将 Python PNG 编码归因于浏览器，也不能将换显示界面视为多路算力问题的整体解法。

页面同时显示最近 120 个逻辑生成样本和实际渲染样本的 p50、p95 和最大生成墙钟耗时，并显示 GPU submission 计数；有限 runner 的 `summary.json` 另保存整个有限运行的最大值。

P2 串行复测（4 站基线配置、暖机 5 步、采样 60 个逻辑组，不含预览输出）如下：

| 像素策略 | GPU 提交数 | 全部逻辑步均值 / p50 / p95 / 最大 ms | 实际渲染步 p50 / p95 / 最大 ms |
| --- | ---: | --- | --- |
| 每次曝光提交 | 480 | 57.94 / 56.86 / 66.55 / 69.97 | 56.86 / 66.55 / 69.97 |
| 每 3 次曝光提交 | 160 | 38.66 / 28.97 / 63.67 / 74.06 | 57.65 / 69.15 / 74.06 |

本次保留了用户已有预览进程，负载未隔离；样本只覆盖约 2 秒，不含完整 CV/融合链路。降频减少总 GPU 工作量与平均负载，未证明单次渲染最大耗时降低；串行背压避免追赶队列，但不是操作系统/GPU 的硬截止保证。预算选择和长期尾部稳定性仍需人工复查后的独立测量。

上述为 P2 当时的测量，不能代表后续代码或硬件的性能。当前可编辑测试场景、无视频运行及中心端分步调试见 [场景 JSON 与中心端开发](../scenarios/README.md)；运行结果为本地生成文件，不纳入源码版本。

复测时先停止或暂停其他预览，再串行运行：

```sh
uv run python scripts/benchmark_scene.py --stations 1 --preview selected
uv run python scripts/benchmark_scene.py --stations 4 --preview selected
uv run python scripts/benchmark_scene.py --stations 4 --preview all
# 不含预览元数据、编码和 JSON 的纯生成基准
uv run python scripts/benchmark_scene.py --stations 4 --preview none
```

可调整 `--warmup`、`--samples`。HTTP、浏览器解码与绘制须单独通过页面指标验证。

## 现在可以安排的人工测试

建议本轮提交后立即做一次 10–15 分钟的视觉和操作验收：

1. 默认启动，确认主辅彩色视频持续更新，主画面能分辨球、盒和飞机轮廓，辅助画面能看到黑白参考面板；确认画面存在真实 RGB 通道差异。
2. 观察至少一个完整循环（默认演示与 review JSON 均为 24 秒），确认运动连续、尺寸随距离变化，地物正确挡住部分或全部目标，循环后时间回到起点。
3. 暂停后确认画面和实验时间停止；单步仅推进一步；回到起点显示第一帧。再播放确认恢复更新。
4. 开关真值叠加，检查标签只影响显示；对比目标状态表和主画面，理解中心被挡但部分轮廓可见的情况。
5. 拖动、缩放场景总览，检查三类对象、视锥和速度箭头；两站启动时切换站点，确认视频和捕获状态一起切换。
6. 核对主辅输出为 1920×1080 / 640×480，记录生成、GPU、其余成像、PNG、浏览器解码耗时；多站模式暂停时切站，确认主辅视频来自选中站点且实验时间不推进。

后续人工验收节点：起伏地形与环境效应接入后检查视觉合理性；普通发包和在线链路接通后检查端到端数据；正式实验前完成标准 profile 的性能与长时间运行验收。
