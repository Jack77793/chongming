# 虚拟场景运行说明

唯一需求来源是根目录 [虚拟场景需求清单](../虚拟场景需求清单.md)。本文只记录当前实现和启动方法。

## 当前实现与验证基线

虚拟环境模块已经完成当前阶段范围内的系统启动、场景配置、离散时钟、Godot 绘制、视频输出、真值输出、OSM 地景和原生 freeview。本文记录已交付接口、运行方法和明确边界；未列入本阶段的检测、标定和中心融合能力仍由其他模块负责。

Python 维护配置解析、场景真值和实验时间；Godot 构造视觉几何、管理实例与材质并输出像素。现有乔木、灌木和草使用随仓库分发的 Shapespark CC0 低模卡片资产，已能展示完整树冠、灌木和草丛；视觉细节不改变简化遮挡代理的判定规则。

自写 Swift/Metal 渲染路线已移除，统一采用 Godot 4.7.2 与 Compatibility 后端建立 Windows、Linux、macOS 的共同运行基础。目前完成 macOS Apple Silicon 的实际运行与测试，Windows/Linux 的图形启动和视觉检查仍待完成，尚不能宣称三平台均已实测通过。

验证基线为 macOS 上 124 项自动化测试通过，覆盖系统契约、场景逻辑、真实渲染接入、Godot 植被生成与资源复用、freeview 共享场景与编辑事务，以及摄影环境/抖动。复查时运行：

```sh
CHONGMING_GODOT=/path/to/godot uv run python -m unittest discover -s tests -q
```

测试需要实际 Godot 可执行文件和图形会话；自动检查不能替代树木外观与跨平台的人工验收。

## 依赖与启动

Python 依赖由 `uv sync` 安装。另需 **Godot 4.7.2 stable 标准版**（不需要 .NET 或导出模板）；启动时检查版本，不符合即报错。Windows、Linux、macOS 使用相同版本和 Compatibility 渲染方式；目前实测平台为 macOS Apple Silicon，其他平台仍需验证。

将 Godot 可执行文件加入 PATH，命名为 `godot4` 或 `godot`；也可以设置 `CHONGMING_GODOT` 指向实际可执行文件。macOS 示例：

```sh
export CHONGMING_GODOT="/Users/Administrator/Downloads/Godot.app/Contents/MacOS/Godot"
uv sync
uv run chongming-preview --scenario scenarios/review.json
```

Windows PowerShell 使用 `$env:CHONGMING_GODOT = 'C:/Tools/Godot/Godot.exe'`；Linux 使用 `export CHONGMING_GODOT=/path/to/godot`。路径中的版本和架构应与当前系统匹配。

预览默认打开 <http://127.0.0.1:8765/>；`--no-browser --port 8766` 可另选端口。Ctrl+C 关闭生产线程、socket 和 Godot 进程。中心工具和有限导出方法见 [场景 JSON 说明](../scenarios/README.md)。

## 场景编辑与原生自由视角

使用 authoring JSON 启动预览后，页面的“进入编辑”取得独占会话锁，并暂停实验时钟。Web 面板只负责相机站、飞行物的增删与位置/朝向/速度修改，以及固定本地 OSM 资产切换；草稿仍由 Python 编译校验，只有“提交 JSON”才会原子写回唯一事实源。外部文件已改变时拒绝提交；“撤销”重新载入磁盘文件。会话 token 限定编辑操作，其他页面不能修改正在编辑的草稿；关闭服务会撤销未提交的草稿。

Web 端不再自行绘制或镜像 3D 场景，也不接收静态地景几何；3D 预览和交互完全在 Godot freeview 独立窗口中完成，浏览器与 Godot 双窗口并用。`/api/preview` 仅保留相机视频、飞行物/可见性和帧真值等动态监视数据。

编辑时 Godot 从原先最小化的进程窗口切换为交互式 freeview：右键拖动看向，按住右键时 WASD 平移、Q/E 升降、Shift 加速；显示相机视锥、目标标签和原生帧率。Godot 在窗口中按显示节拍连续绘图，传感器像素请求停止且实验保持暂停；草稿改变后推送新的逻辑场景快照。非编辑时也可在页面打开 freeview，此时它只随最新离散场景步更新，不抢占实验时钟；关闭窗口或按钮即可回到最小化低开销模式。鼠标和键盘交互完全在 Godot freeview 窗口内完成；页面只保留“打开/关闭 freeview”开关，不传输或重建 3D 画面。退出编辑后恢复编辑前的播放/暂停、视频和 freeview 状态，标记不会混入传感器帧。帧率受实际显卡、窗口状态和地景复杂度影响，界面显示的是本机当前测量值，而非保证的固定值。

目前只有已校验的本地 Hannover 资产可从面板选择；Manhattan 尚无固定资产，因此不会出现一个无法复现的占位选项。合成 OSM 示例可用于离线试操作；真实样区仍需本地预备资产，见 [OSM 地景整合说明](OSM地景整合说明.md)。

当前 macOS M4 / Godot 4.7.2 Compatibility / 1024×640 的本地 Hannover 约 1×1 km 样区（1160 个地物/植被）编辑概览实测显示 100 FPS；此值受进程的 100 FPS 上限限制，仅表示该视角的本机结果，不代表近景或其他平台的性能保证。

Godot 随虚拟场景模块启动，包括关闭视频的运行；版本或图形上下文不可用时明确失败。实际绘制使用持久的 SubViewport 和 3D 场景，要求可用的图形会话及 OpenGL 3.3 驱动。Linux 无桌面环境需要另行提供图形会话（例如 Xvfb 与合适的驱动，尚未实测）。不能使用 `--headless`：该模式选择 dummy renderer，无法产生真实场景像素。平常最小化其工具窗口；编辑时显示为交互式场景查看器。macOS 可能显示 Dock 图标。

## 时间、视频和测量

Python 掌握实验时钟、配置、轨迹、相机位姿与受保护真值；向 Godot 发送不可变语义快照，Godot 负责场景树、程序化视觉几何和 RGB8 绘制，不依赖墙钟推进场景。视线遮挡使用逻辑层简化代理（树木为等效圆柱），与高细节视觉网格解耦；未来可将批量遮挡查询移入 Godot 并回传 ID/结果，需保持同一代理规则和离散采样时刻。

原生配置为主相机 1920×1080、对角线 FOV 60°，辅相机 640×480、水平 FOV 2.6°，默认都为 30 fps。辅助相机保持水平，朝向自己 ID 绑定的横向 A4 棋盘中心，距离 10 m。主相机实际朝向直接写入元数据。像素是无 alpha 的 sRGB；多次曝光采样先解码为线性能量、积分及添加传感器噪声，再编码为 sRGB。

`--render-fps 8` 限制预览的墙钟生产节拍；源端还按每个相机的独立采样计数降低像素请求频率。`--no-video` 停止像素请求，保留全部逻辑步、普通事件、真值和耗时。Godot 的自动渲染循环关闭，仅收到快照时强制绘制一次；暂停或无视频时没有持续绘图。原生采样率与渲染节拍是两个参数，不追赶丢弃实验步。

每个逻辑组保留逻辑、真值、成像、事件与总体耗时，以及跳过帧 ID 和实际请求次数；预览展示 p50/p95/最大值。历史 JSON 字段 `gpu_ms` 现表示 Godot 内的场景更新、同步、绘制及回读墙钟耗时，`gpu_submissions` 表示像素请求次数，不能解释为纯 GPU 硬件计时或驱动提交数。Godot 启动、IPC 与 Python 图像处理成本另体现在总墙钟耗时中。

## 已实现的基础能力

- OSM 离线地景资产：本地 XML 清洗、WGS84→ENU、建筑/道路/树点/森林/绿地/水体分类、可选 EGM96 HGT DEM、摘要校验和共享遮挡/渲染网格；预览回调不推进实验时间。`scenarios/osm_landscape.json` 为合成示例，汉诺威样区复查产物在 `output/osm/hannover-500m/`，详见 [OSM 地景整合说明](OSM地景整合说明.md)。
- 已完成：真实 3D 平地/高度网格、建筑等静态物体、卡片树/灌木/草、球/盒/网格飞行器、简化逻辑遮挡、基础方向光与阴影；直线和圆弧轨迹；站点、相机、目标初始元数据；独立 A4 定标板。
- 已完成：JSON 场景编译、统一硬编码种子 42、普通视频/伪装发包/受保护真值三路输出；主辅相机独立降采样；Godot freeview 中的设备 ID、视锥、飞行器名称/ID/速度矢量；目标中心在视场内且未被地形、地物或其他飞行器遮挡时才产生普通射线。
- 已实现确定性风摆：固定种子派生每棵树相位，平均风和按实验时钟平滑采样的湍流共同驱动树冠；Godot 把采样到的树冠倾斜换算为整坨树冠的三轴平移和轻微缩放，树干保持静止。它是低成本可复现的简化模型，不是流固耦合或枝叶级形变。Python 仍用稳定的圆柱树干/树冠代理判断遮挡。
- 当前植被使用随仓库分发的 [Shapespark Low-Poly Exterior Plants Kit](https://github.com/shapespark/shapespark-assets/tree/main/shapespark-low-poly-plants-kit)（CC0 1.0，见 `src/chongming/rendering/godot/assets/`）。GLTF 在运行时由 `GLTFDocument` 加载，12 个乔木变体、6 个灌木/绿篱变体和 12 个草/地被变体共享网格/材质；单棵乔木 368–646 个三角形，卡片材质使用 alpha scissor。乔木拆成树干 surface 和树冠卡片 surface，树冠接收整坨平移/缩放；草 patch 用共享草簇网格的 `MultiMesh` 填充。品种由世界坐标的低频全局噪声加局部哈希选择，密度由独立的低频噪声形成林地/草地斑块；Python 仍只发送语义尺寸和稳定种子，不发送顶点/实例变换。
- 已实现摄影环境：太阳可见光盘、瑞利散射外观近似的天空渐变、随深度衰减的大气透视，以及可选的曝光压制、亮部扩散与太阳幕光。光盘由天空绘制，实际几何自然遮挡；后处理从渲染图像采样亮部，不向 Python 回传测光状态。照度仍归一化用于显示，大气与光学均为未标定的视觉近似，不能用 RGB 数值考核真实相机的辐射响应或测光精度。
- 已实现确定性相机旋转抖动：Python 按固定种子与实验时间直接计算姿态和角速度；使用正交旋转，统一驱动投影、几何遮挡、真值、普通射线与渲染。支持角幅度或等效像素幅度，不以图片平移模拟。默认关闭，示例只开启主相机。
- 已实现首版非体积云：1–2 层程序 Perlin/Voronoi 云，使用低频 UV 扭曲并按实验时间平移；云量衰减太阳光盘和直射光。云保持视频侧天气干扰，不反向改变 Python 几何真值或普通射线。
- 植被扩展为乔木、灌木和草：乔木 12 个卡片变体、灌木/绿篱 6 个、草/地被 12 个。LOD 按树高在屏幕上的投影像素数判断：近景保留完整卡片树、阴影和风摆；中景保留卡片树但关闭阴影和风摆；远景使用 `assets/impostors/` 中预渲染的交叉 billboard，单 surface、无阴影、无动画；草按 `vegetation_lod_near_m` 剔除。当前没有交叉淡入或全局 MultiMesh 合批，阈值处仍可能 pop。新增程序地表/地被材质、Compatibility SSAO、四邻域快速边缘 AA 和固定 8 样本屏幕空间光束，全部显式 opt-in。

## 摄影环境复查与边界

启动 `uv run chongming-preview --scenario scenarios/photography.json` 查看逆光、远景衰减和主相机抖动；配置参数见 [场景 JSON 说明](../scenarios/README.md)。现有演示场景维持基础照明，环境效果需显式开启。

环境效果是显式 opt-in：场景没有写 `environment` / `clouds` 时只绘制默认天空渐变，不会出现太阳光盘、云层、雾/大气透视。Hannover 本地 review 场景已启用 `environment` 和云层；若主相机仰角很高，画面可能只有天空、云和太阳，地面大气透视需要地平线或地面进入视场，可降低仰角或用 Godot freeview 观察。

```sh
CHONGMING_GODOT=/path/to/godot uv run python scripts/review_photography.py --output output/photography-review --samples 6
```

脚本在同一进程、同一离散时刻依次输出基础画面、大气/云、完整摄影效果和暗物体遮住太阳四张图，生成 `comparison.png` 与 `timing.json`。当前 macOS M4 / Godot 4.7.2 Compatibility / 1024×576 的一次六样本暖机测量，基础约 15 ms、大气与云约 20 ms、完整效果约 25 ms；包括更新、同步、绘图与回读，不是纯 GPU 计时，也不能与不同场景/分辨率的植被测量直接比较。

天空与光学材质跨请求复用；基础场景只绘制一个 SubViewport，开启光学增加一次 2D 后处理绘制。两者都按请求更新，不在暂停或关闭视频时持续绘制。曝光按当前图像的固定采样网格和太阳位置测光，无墙钟适应、随机噪声或跨帧历史；暂停、跳过像素或改变相机顺序不会积累曝光状态。实际传感器噪声与多次曝光积分仍由既有成像链处理。

太阳测光是图像亮度近似：暗遮挡物能压掉太阳信号，亮白物体则可能被识别为亮源；不模拟真实镜头鬼影。晴空大气透视使用 Godot 深度雾，参数按指数消光启发式换算，不等于已实现气象雾，更不触发发包距离硬截断。普通射线继续按几何可见性生成，便于中心端独立开发；视频中的远处目标可能已难以检测。

自动检查验证同进程切换效果不会留下旧天空/雾/像素、暗物体挡住太阳后曝光压制减弱、远物体比近物体受更多大气影响、抖动回放一致且角速度符合姿态导数。断言使用行为关系与宽容差，不维护跨 GPU 像素 golden。

## 植被复查与性能边界

- 可用 `CHONGMING_GODOT=... uv run python scripts/review_vegetation.py --output output/vegetation-review --samples 12` 生成近景、群落和叶片特写，报告首请求、暖机耗时和同进程空植被对照。当前 macOS M4 / Godot 4.7.2 Compatibility 的三棵树 1024×768 实测暖机约 17–19 ms/帧，空植被对照约 18 ms；首次请求约 0.95 s，包含 GLTF 资源加载与图形初始化。Hannover 地面复查（1024×576，单相机、3795 个植被规格）暖机约 43–48 ms，首请求约 1.4–1.6 s，Godot RSS 约 541 MB；近森林复查约 69–81 ms，RSS 约 573 MB。旧的程序化树基线为 22/18 ms、RSS 1.42–1.48 GB、首请求约 2.78 s。卡片树和更密的 OSM 植被显著增加了视觉密度，同时降低了内存和首请求；但当前逐树节点、近景完整卡片树和阴影仍使帧时间高于旧基线，下一步需要用空间分块 MultiMesh 合批。测量包括场景同步、绘制和像素回读，不是纯 GPU 时间；不同相机和场景之间的数值不能直接互相换算。
- 这版树木已达到“可辨识的完整树冠、可复现变体和材质细节”验证目标，但不是某一树种的精确植物学模型：树冠细节来自预制作卡片纹理，近看仍能看出卡片平面；12 个乔木变体、6 个灌木/绿篱变体、12 个草/地被变体通过世界坐标全局噪声和局部哈希选择。LOD 使用屏幕投影尺寸，远景 billboard 无阴影/动画；树冠风摆仍是整坨三轴平移/轻微缩放，没有枝叶级形变；草簇关闭了阴影。逻辑遮挡继续使用圆柱等效轮廓，视觉细节不会改变真值判定规则。

## 当前边界与下一阶段

- 当前边界：乔木/灌木/草已替换为 CC0 卡片资产，并按屏幕尺寸切换近/中/远景；没有交叉淡入或全局 MultiMesh 合批，逐树节点和阴影仍使近景帧时间高于旧基线；风摆仍是整坨平移/缩放，不是枝叶级风场。
- OSM 已完成离线建筑、道路、树点、森林/绿地/水体和可选 DEM 导入；运行时只读本地可复现资产。当前汉诺威约 1×1 km 样区已实测，3 km 范围和选区交互仍待后续。用法、参考代码、HGT 基准、许可和当前支持范围见 [OSM 地景整合说明](OSM地景整合说明.md)。
- 摄影环境仍是视觉近似；雨、气象雾以及厚云对像素与真值的统一影响尚未建模。当前不承诺摄影难度已与真实数据集等价。
- 待验证：Windows/Linux 图形启动、窗口行为和人工视觉验收。理论可复现性以几何、时间、事件和数据输出检查；不做跨 GPU 的像素级 golden。

旧的渲染器需求说明已删除；此实现没有自写 Swift/Metal 后端，系统图形驱动内部如何实现 Godot 渲染不属于场景接口。
