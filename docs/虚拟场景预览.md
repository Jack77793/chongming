# 虚拟场景运行说明

唯一需求来源是根目录 [虚拟场景需求清单](../虚拟场景需求清单.md)。本文只记录当前实现和启动方法。

## 依赖与启动

Python 依赖由 `uv sync` 安装。另需 **Godot 4.7.2 stable 标准版**（不需要 .NET 或导出模板）；启动时检查版本，不符合即报错。Windows、Linux、macOS 使用相同版本和 Compatibility 渲染方式；目前实测平台为 macOS Apple Silicon，其他平台仍需验证。

将 Godot 可执行文件加入 PATH，命名为 `godot4` 或 `godot`；也可以设置 `CHONGMING_GODOT` 指向实际可执行文件。macOS 示例：

```sh
export CHONGMING_GODOT="/Users/Administrator/Downloads/Godot.app/Contents/MacOS/Godot"
uv sync
uv run chongming-preview --scenario scenarios/review.json
```

Windows PowerShell 使用 `$env:CHONGMING_GODOT = 'C:/Tools/Godot/Godot.exe'`；Linux 使用 `export CHONGMING_GODOT=/path/to/godot`。路径中的版本和架构应与当前系统匹配。

预览默认打开 <http://127.0.0.1:8765/>；`--no-browser --port 8766` 可另选端口。Ctrl+C 关闭生产线程、socket 和 Godot 进程。中心工具和有限导出方法见 [场景 JSON 说明](../scenarios/README.md)。

Godot 随虚拟场景模块启动，包括关闭视频的运行；版本或图形上下文不可用时明确失败。实际绘制使用持久的 SubViewport 和 3D 场景，要求可用的图形会话及 OpenGL 3.3 驱动。Linux 无桌面环境需要另行提供图形会话（例如 Xvfb 与合适的驱动，尚未实测）。不能使用 `--headless`：该模式选择 dummy renderer，无法产生真实场景像素。当前创建最小化的工具窗口，macOS 可能显示 Dock 图标；它不是独立的场景查看器。

## 时间、视频和测量

Python 掌握实验时钟、配置、轨迹、相机位姿与受保护真值；向 Godot 发送不可变语义快照，Godot 负责场景树、程序化视觉几何和 RGB8 绘制，不依赖墙钟推进场景。视线遮挡使用逻辑层简化代理（树木为等效圆柱），与高细节视觉网格解耦；未来可将批量遮挡查询移入 Godot 并回传 ID/结果，需保持同一代理规则和离散采样时刻。

原生配置为主相机 1920×1080、对角线 FOV 60°，辅相机 640×480、水平 FOV 2.6°，默认都为 30 fps。辅助相机保持水平，朝向自己 ID 绑定的横向 A4 棋盘中心，距离 10 m。主相机实际朝向直接写入元数据。像素是无 alpha 的 sRGB；多次曝光采样先解码为线性能量、积分及添加传感器噪声，再编码为 sRGB。

`--render-fps 8` 限制预览的墙钟生产节拍；源端还按每个相机的独立采样计数降低像素请求频率。`--no-video` 停止像素请求，保留全部逻辑步、普通事件、真值和耗时。Godot 的自动渲染循环关闭，仅收到快照时强制绘制一次；暂停或无视频时没有持续绘图。原生采样率与渲染节拍是两个参数，不追赶丢弃实验步。

每个逻辑组保留逻辑、真值、成像、事件与总体耗时，以及跳过帧 ID 和实际请求次数；预览展示 p50/p95/最大值。历史 JSON 字段 `gpu_ms` 现表示 Godot 内的场景更新、同步、绘制及回读墙钟耗时，`gpu_submissions` 表示像素请求次数，不能解释为纯 GPU 硬件计时或驱动提交数。Godot 启动、IPC 与 Python 图像处理成本另体现在总墙钟耗时中。

## 已完成与后续阶段

- 已完成：真实 3D 平地/高度网格、建筑等静态物体、Godot 原生程序树干/分枝/叶簇、球/盒/网格飞行器、简化逻辑遮挡、基础方向光与阴影；直线和圆弧轨迹；站点、相机、目标初始元数据；独立 A4 定标板。
- 已完成：JSON 场景编译、统一硬编码种子 42、普通视频/伪装发包/受保护真值三路输出；主辅相机独立降采样；总览中的设备 ID、视锥、飞行器名称/ID/速度矢量；目标中心在视场内且未被地形、地物或其他飞行器遮挡时才产生普通射线。
- 下一阶段：太阳可见光盘、曝光压制/炫光/光晕、瑞利天空/大气透视、微小相机抖动。当前只是基础照明和纯色天空，不能视为已完成摄影环境模拟。
- 当前光照采用用于显示的照度归一化基准，并非经标定的辐射/曝光模型；不能用当前 RGB 数值验证真实相机的测光性能。
- 已实现首版树木及确定性风摆：固定种子派生每棵树相位，平均风和按实验时钟平滑采样的湍流共同驱动树冠绕树冠基部微幅转动；Godot 按语义尺寸生成树木视觉网格，Python 使用稳定的圆柱树干/树冠代理判断遮挡。它是低成本可复现的简化模型，不是流固耦合或真实冠层变形。待评估草本覆盖率、树种外观、叶簇层级及风力的物理标定。
- 当前植被实现重点验证 Godot 侧程序化生成和实例化：树干、主枝、细枝由 Godot `SurfaceTool` 生成；一片折叠的尖叶作为共享 `ArrayMesh` 原型，由 `MultiMeshInstance3D` 批量实例化。每棵树的种子由稳定的植被 ID 派生，位置、姿态、尺度和颜色都在 Godot 侧确定；Python 不再发送叶片顶点或实例变换。每冠 2592 片叶，叶片和枝干都保留 Godot 的实时阴影；自动生成局部包围盒，叶片原型跨树共享，姿态或相机变化复用已生成资源。
- 可用 `CHONGMING_GODOT=... uv run python scripts/review_vegetation.py --output output/vegetation-review --samples 12` 生成近景、群落和叶片特写，报告首请求、暖机耗时和同进程空植被对照。当前 macOS M4 / Godot 4.7.2 Compatibility 的三棵树 1024×768 实测暖机约 85--95 ms/帧；首次请求约 0.33 s，包含资源创建及图形初始化。但同期移除全部植被也约 80--90 ms/帧，降低密度或关闭叶片阴影未表现出稳定收益，因此不能将这些墙钟耗时全部归因于树木，也不能据此推断植被规模上限。测量包括场景同步、绘制和像素回读，不是纯 GPU 时间；大场景性能仍需独立验证。
- 这版树木已达到“可辨识的枝干、细枝、独立叶片和可复现实例”验证目标，但仍不是某一树种的精确植物学模型：叶片无外部贴图，枝条规则性较高，远距离 LOD、草本覆盖、真实风场和材质贴图留待后续。逻辑遮挡继续使用圆柱等效轮廓，视觉细节不会改变真值判定规则。
- 后续困难项：太阳可见光盘/曝光压制/炫光、瑞利天空和大气透视，以及雨、雾、云对像素与真值的统一影响。云雾是否阻止伪装发包，需要约定能见度/透射率判据，避免画面与射线真值矛盾。
- 待实测：Windows/Linux 图形启动、窗口行为和人工视觉验收。理论可复现性以几何、时间和数据输出检查；不做跨 GPU 的像素级 golden。

旧的渲染器需求说明已删除；此实现没有自写 Swift/Metal 后端，系统图形驱动内部如何实现 Godot 渲染不属于场景接口。
