# 虚拟场景视频预览

本轮提供可独立启动的虚拟场景子系统。它复用场景时钟、逻辑快照、投影、遮挡与成像接口，输出由 Apple Metal GPU 生成的真实几何 RGB8 视频；完整设备检测、标定和中心融合运行链路仍在后续开发范围。

## 启动

在仓库根目录执行：

```sh
uv sync
uv run chongming-preview
```

也可以执行 `uv run python -m chongming`。默认启动本地服务并自动打开浏览器，地址为 <http://127.0.0.1:8765/>。终端按 Ctrl+C 停止。

```sh
# 不自动打开浏览器，改用 8766 端口
uv run chongming-preview --no-browser --port 8766

# 两站预览；支持 1–4 个站点
uv run chongming-preview --stations 2

# 原始需求的标准相机配置
uv run chongming-preview --baseline
```

默认显式使用实验 profile：主相机 640×360、辅助相机 320×240、15 fps；可用 `--fps 1` 至 `--fps 60` 调整实验采样率。`--baseline` 固定使用主相机 1920×1080、辅助相机 640×480、30 fps 的采样计划，并忽略 `--fps`。两种配置的对角线 FOV 均为主相机 60°、辅助相机 20°，辅助相机保持水平安装。

运行要求 macOS、可用的 Apple Metal GPU 和 Swift 编译器（Xcode Command Line Tools）。首次启动会在 `.codex-cache/` 编译原生进程；该目录是本地构建缓存。

像素生成使用持久化 Swift/Metal 子进程的 compute shader；Python 负责逻辑真值、场景序列化、RGB8 回读及传感器后处理。没有 Metal 时启动会明确失败，不会退回 CPU 像素渲染。GPU buffer 按容量复用，请求串行处理，直接回传紧密 RGB8，避免 RGBA 拆通道和重复整帧复制。正常 Ctrl+C 会先停止生产线程，再通过 stdin EOF 关闭原生进程、释放管道。

浏览器 Canvas 显示已经生成的视频和场景监视视图。预览采用无损 PNG，原始 `CameraFrame` 为 `rgb8`。所有相机的原始帧照常生成；PNG/Base64 只按查看请求编码选中站点的主辅两路，编码不在模拟生产线程执行。没有查看者时不编码，暂停时复用缓存，同一序号不重复传输图像。只保留最新模拟步骤及其各站点的预览缓存，不积累历史帧。

采样时间由实验时钟确定。机器算不过来时播放变慢，不丢弃模拟步骤，也不改写帧时间戳。页面允许跳过已经过时的显示快照；请求之间至少间隔 60 ms，预览显示率不等于原始采样率。

## 本轮内容

三类对象都有具体实例：世界物体包含平面地形、建筑、球形地物和固定黑白参考面板；摄像机包含每站独立主辅相机；飞行物包含球、盒和简化飞机三角网格。飞行物沿确定性轨迹运动，24 秒场景自动循环。

成像使用实际光学姿态和内参，在 GPU 上计算物体表面、轮廓、深度遮挡和基础彩色光照；Python 保留曝光多次采样、确定性传感器噪声与 RGB8 裁剪。飞行物中心不可捕获时，仍可能看到未遮挡的部分轮廓。主相机捕获状态按需求中的“中心在视场内且中心视线无遮挡”判定，不等同于任意像素可见。

页面提供播放/暂停、单步、回到起点、站点切换以及可旋转/缩放的场景总览。真值叠加默认关闭；打开后显示投影框与目标 ID，叠加只发生在预览画布，原始 `CameraFrame` 不含真值标签。场景总览显示摄像机视锥、目标速度和遮挡交点。回到起点与自动循环均创建新图像/虚拟事件会话，暂停状态下回到起点会发布第一帧并继续暂停。

当前只支持平面地形、无畸变相机和清洁环境。起伏地形、大气透视、复杂天气/自动曝光、GPU 镜头畸变以及普通校准和射线伪装发包尚未完成；非平面地形和非零畸变会明确报错。预览不代表这些原始需求已验收完成。旧需求文档中的首版 `gray8` 约定以用户最新的 RGB8 要求为准。

## 性能测量与 Web 判断

页面的“生成”是全部相机的场景逻辑、成像及监视元数据墙钟时间，不含 PNG；“PNG 编码”包含选中站点的两路 PNG/Base64。“GPU”使用 Metal command 的 GPU 时间；“其余成像”是成像模块墙钟时间减 GPU 时间，包含序列化、IPC、调度等待、回读、后处理及真值组装，不能解释为纯 CPU 执行时间或利用率。

浏览器的“请求”包含服务端编码、等待、传输和读取响应；“JSON 解析”只计 `JSON.parse`。“解码”计 data URL 设置和并行 `Image.decode()` 的墙钟时间；“绘制调用”计 Canvas 提交及视频 DOM 组装，未覆盖完整 GPU 合成和屏幕呈现。

2026-10-13 在 Apple M4 / 24 GB / macOS 26.6 上停止其他预览生产负载后，暖机 5 步、采样 30 步的同步基准结果如下（均为平均 ms；不含 HTTP 与浏览器）：

| 基准 | 原始帧生成 | GPU | 其余成像 | 场景逻辑/事件 | 监视元数据 | PNG/Base64 | JSON |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 站 / 查看该站 | 17.06 | 2.89 | 4.71 | 9.46 | 0.66 | 15.08 | 0.81 |
| 4 站 / 查看 1 站 | 63.78 | 15.35 | 15.98 | 32.45 | 1.85 | 12.97 | 1.55 |
| 4 站 / 对照编码全部站 | 61.58 | 14.43 | 15.64 | 31.51 | 1.94 | 49.63 | 2.39 |

这组数据只覆盖场景开头约一秒，不能代替完整轨迹和长时间性能验收，亦不作为不同运行条件下的严格提速比例。四站原始帧生成范围约 55–77 ms，尚未达到 30 fps 的 33.3 ms 预算。并行运行 CV 和中心算法的性能尚未验证。

浏览器实测中，旧版四站全部八路解码的 8 个样本约 13–17 ms；按需版两路解码样本约 4–7 ms，绘制调用约 0.2–0.8 ms。这些小样本不能代表最差延迟。服务端 PNG 和逻辑遮挡计算已显示明确开销，目前保留网页。只有在减少预览编码/传输、明确测出浏览器解码或完整呈现仍超预算后，再比较原生显示方案；不能将 Python PNG 编码归因于浏览器，也不能将换显示界面视为多路算力问题的整体解法。

复测时先停止或暂停其他预览，再串行运行：

```sh
uv run python scripts/benchmark_scene.py --stations 1 --preview selected
uv run python scripts/benchmark_scene.py --stations 4 --preview selected
uv run python scripts/benchmark_scene.py --stations 4 --preview all
# 不含预览元数据、编码和 JSON 的纯生成基准
uv run python scripts/benchmark_scene.py --stations 4 --preview none
```

可调整 `--warmup`、`--samples`。HTTP、浏览器解码与绘制须单独通过页面指标验证。

## 现在可以安排的人工测试

建议本轮提交后立即做一次 10–15 分钟的视觉和操作验收：

1. 默认启动，确认主辅彩色视频持续更新，主画面能分辨球、盒和飞机轮廓，辅助画面能看到黑白参考面板；确认画面存在真实 RGB 通道差异。
2. 观察至少一个完整的 24 秒循环，确认运动连续、尺寸随距离变化，地物正确挡住部分或全部目标，循环后时间回到起点。
3. 暂停后确认画面和实验时间停止；单步仅推进一步；回到起点显示第一帧。再播放确认恢复更新。
4. 开关真值叠加，检查标签只影响显示；对比目标状态表和主画面，理解中心被挡但部分轮廓可见的情况。
5. 拖动、缩放场景总览，检查三类对象、视锥和速度箭头；两站启动时切换站点，确认视频和捕获状态一起切换。
6. 按需启动 `--baseline` 核对主辅分辨率，记录生成、GPU、其余成像、PNG、浏览器解码耗时；这一项先检查正确性，实时性能另行验收。多站模式暂停时切站，确认主辅视频来自选中站点且实验时间不推进。

后续人工验收节点：起伏地形与环境效应接入后检查视觉合理性；普通发包和在线链路接通后检查端到端数据；正式实验前完成标准 profile 的性能与长时间运行验收。

自动验证命令：

```sh
uv run python -m unittest discover -s tests -v
uv run ruff check src tests
uv run mypy -p chongming
```
