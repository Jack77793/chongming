# 虚拟场景运行说明

唯一需求来源是根目录 [虚拟场景需求清单](../虚拟场景需求清单.md)。本文只记录当前实现和启动方法。

## 阶段里程碑（2026-10-19）

虚拟环境模块已初步建立，系统启动、场景配置、离散时钟、Godot 绘制、视频输出与真值输出的基本流程已经验证。本阶段验证了 Godot 的程序化植被能力，并完成渲染职责迁移；这是基础流程里程碑，不代表需求清单已经全部完成。

Python 维护配置解析、场景真值和实验时间；Godot 构造视觉几何、管理实例与材质并输出像素。现有树木已能展示枝干、细枝、独立叶片和阴影，后续重点是调整枝叶分布、比例与颜色以贴近真实树木，同时权衡计算量与开发成本。视觉细节不改变简化遮挡代理的判定规则。

自写 Swift/Metal 渲染路线已移除，统一采用 Godot 4.7.2 与 Compatibility 后端建立 Windows、Linux、macOS 的共同运行基础。Windows/Linux 原生桌面的窗口行为和人工视觉检查仍待完成，尚不能宣称三平台均已完成验收。

本阶段验证基线为 macOS 上 85 项自动化测试通过，覆盖系统契约、场景逻辑、真实渲染接入、Godot 植被生成与资源复用，以及摄影环境/抖动。复查时运行：

```sh
CHONGMING_GODOT=/path/to/godot uv run python -m unittest discover -s tests -q
```

测试需要实际 Godot 可执行文件和图形会话；自动检查不能替代树木外观与跨平台的人工验收。

## 依赖与启动

使用 Nix 时，按 [Nix 开发环境](Nix开发环境.md) 执行 `nix develop`，无需 `uv sync` 或手工设置 Godot 路径；Linux 无桌面环境可使用其中的 `software` shell。

以下为非 Nix 路线。Python 依赖由 `uv sync` 安装。另需 **Godot 4.7.2 stable 标准版**（不需要 .NET 或导出模板）；启动时检查版本，不符合即报错。Windows、Linux、macOS 使用相同版本和 Compatibility 渲染方式。

将 Godot 可执行文件加入 PATH，命名为 `godot4` 或 `godot`；也可以设置 `CHONGMING_GODOT` 指向实际可执行文件。macOS 示例：

```sh
export CHONGMING_GODOT="/Users/Administrator/Downloads/Godot.app/Contents/MacOS/Godot"
uv sync
uv run chongming-preview --scenario scenarios/review.json
```

Windows PowerShell 使用 `$env:CHONGMING_GODOT = 'C:/Tools/Godot/Godot.exe'`；Linux 使用 `export CHONGMING_GODOT=/path/to/godot`。路径中的版本和架构应与当前系统匹配。

预览默认打开 <http://127.0.0.1:8765/>；`--no-browser --port 8766` 可另选端口。Ctrl+C 关闭生产线程、socket 和 Godot 进程。中心工具和有限导出方法见 [场景 JSON 说明](../scenarios/README.md)。

Godot 随虚拟场景模块启动，包括关闭视频的运行；版本或图形上下文不可用时明确失败。实际绘制使用持久的 SubViewport 和 3D 场景，要求可用的图形会话及 OpenGL 3.3 驱动。Linux 无桌面环境可使用 Nix 的 `software` shell 提供 Xvfb/Mesa 图形上下文。不能使用 `--headless`：该模式选择 dummy renderer，无法产生真实场景像素。当前创建最小化的工具窗口，macOS 可能显示 Dock 图标；它不是独立的场景查看器。

## 时间、视频和测量

Python 掌握实验时钟、配置、轨迹、相机位姿与受保护真值；向 Godot 发送不可变语义快照，Godot 负责场景树、程序化视觉几何和 RGB8 绘制，不依赖墙钟推进场景。视线遮挡使用逻辑层简化代理（树木为等效圆柱），与高细节视觉网格解耦；未来可将批量遮挡查询移入 Godot 并回传 ID/结果，需保持同一代理规则和离散采样时刻。

原生配置为主相机 1920×1080、对角线 FOV 60°，辅相机 640×480、水平 FOV 2.6°，默认都为 30 fps。辅助相机保持水平，朝向自己 ID 绑定的横向 A4 棋盘中心，距离 10 m。主相机实际朝向直接写入元数据。像素是无 alpha 的 sRGB；多次曝光采样先解码为线性能量、积分及添加传感器噪声，再编码为 sRGB。

`--render-fps 8` 限制预览的墙钟生产节拍；源端还按每个相机的独立采样计数降低像素请求频率。`--no-video` 停止像素请求，保留全部逻辑步、普通事件、真值和耗时。Godot 的自动渲染循环关闭，仅收到快照时强制绘制一次；暂停或无视频时没有持续绘图。原生采样率与渲染节拍是两个参数，不追赶丢弃实验步。

每个逻辑组保留逻辑、真值、成像、事件与总体耗时，以及跳过帧 ID 和实际请求次数；预览展示 p50/p95/最大值。历史 JSON 字段 `gpu_ms` 现表示 Godot 内的场景更新、同步、绘制及回读墙钟耗时，`gpu_submissions` 表示像素请求次数，不能解释为纯 GPU 硬件计时或驱动提交数。Godot 启动、IPC 与 Python 图像处理成本另体现在总墙钟耗时中。

## 已实现的基础能力

- 已完成：真实 3D 平地/高度网格、建筑等静态物体、Godot 原生程序树干/分枝/叶簇、球/盒/网格飞行器、简化逻辑遮挡、基础方向光与阴影；直线和圆弧轨迹；站点、相机、目标初始元数据；独立 A4 定标板。
- 已完成：JSON 场景编译、统一硬编码种子 42、普通视频/伪装发包/受保护真值三路输出；主辅相机独立降采样；总览中的设备 ID、视锥、飞行器名称/ID/速度矢量；目标中心在视场内且未被地形、地物或其他飞行器遮挡时才产生普通射线。
- 已实现首版树木及确定性风摆：固定种子派生每棵树相位，平均风和按实验时钟平滑采样的湍流共同驱动树冠绕树冠基部微幅转动；Godot 按语义尺寸生成树木视觉网格，Python 使用稳定的圆柱树干/树冠代理判断遮挡。它是低成本可复现的简化模型，不是流固耦合或真实冠层变形。待评估草本覆盖率、树种外观、叶簇层级及风力的物理标定。
- 当前植被实现重点验证 Godot 侧程序化生成和实例化：树干、主枝、细枝由 Godot `SurfaceTool` 生成；一片折叠的尖叶作为共享 `ArrayMesh` 原型，由 `MultiMeshInstance3D` 批量实例化。每棵树的种子由稳定的植被 ID 派生，位置、姿态、尺度和颜色都在 Godot 侧确定；Python 不再发送叶片顶点或实例变换。每冠 2592 片叶，叶片和枝干都保留 Godot 的实时阴影；自动生成局部包围盒，叶片原型跨树共享，姿态或相机变化复用已生成资源。
- 已实现首版摄影环境：太阳可见光盘、瑞利散射外观近似的天空渐变、随深度衰减的大气透视，以及可选的曝光压制、亮部扩散与太阳幕光。光盘由天空绘制，实际几何自然遮挡；后处理从渲染图像采样亮部，不向 Python 回传测光状态。照度仍归一化用于显示，大气与光学均为未标定的视觉近似，不能用 RGB 数值考核真实相机的辐射响应或测光精度。
- 已实现确定性相机旋转抖动：Python 按固定种子与实验时间直接计算姿态和角速度；使用正交旋转，统一驱动投影、几何遮挡、真值、普通射线与渲染。支持角幅度或等效像素幅度，不以图片平移模拟。默认关闭，示例只开启主相机。
- 已实现首版非体积云：1–2 层程序 Perlin/Voronoi 云，使用低频 UV 扭曲并按实验时间平移；云量衰减太阳光盘和直射光。云保持视频侧天气干扰，不反向改变 Python 几何真值或普通射线。
- 植被扩展为乔木、灌木和草：灌木与草均为 Godot 侧确定性 MultiMesh；详细乔木/灌木在近距离绘制，远处换低面代理后剔除，草超过近景阈值直接剔除。新增程序地表细节、Compatibility SSAO、四邻域快速边缘 AA 和固定 8 样本屏幕空间光束，全部显式 opt-in。

## 摄影环境复查与边界

启动 `uv run chongming-preview --scenario scenarios/photography.json` 查看逆光、远景衰减和主相机抖动；配置参数见 [场景 JSON 说明](../scenarios/README.md)。现有演示场景维持基础照明，环境效果需显式开启。

```sh
CHONGMING_GODOT=/path/to/godot uv run python scripts/review_photography.py --output output/photography-review --samples 6
```

脚本在同一进程、同一离散时刻依次输出基础画面、大气/云、完整摄影效果和暗物体遮住太阳四张图，生成 `comparison.png` 与 `timing.json`。当前 macOS M4 / Godot 4.7.2 Compatibility / 1024×576 的一次六样本暖机测量，基础约 15 ms、大气与云约 20 ms、完整效果约 25 ms；包括更新、同步、绘图与回读，不是纯 GPU 计时，也不能与不同场景/分辨率的植被测量直接比较。

天空与光学材质跨请求复用；基础场景只绘制一个 SubViewport，开启光学增加一次 2D 后处理绘制。两者都按请求更新，不在暂停或关闭视频时持续绘制。曝光按当前图像的固定采样网格和太阳位置测光，无墙钟适应、随机噪声或跨帧历史；暂停、跳过像素或改变相机顺序不会积累曝光状态。实际传感器噪声与多次曝光积分仍由既有成像链处理。

太阳测光是图像亮度近似：暗遮挡物能压掉太阳信号，亮白物体则可能被识别为亮源；不模拟真实镜头鬼影。晴空大气透视使用 Godot 深度雾，参数按指数消光启发式换算，不等于已实现气象雾，更不触发发包距离硬截断。普通射线继续按几何可见性生成，便于中心端独立开发；视频中的远处目标可能已难以检测。

自动检查验证同进程切换效果不会留下旧天空/雾/像素、暗物体挡住太阳后曝光压制减弱、远物体比近物体受更多大气影响、抖动回放一致且角速度符合姿态导数。断言使用行为关系与宽容差，不维护跨 GPU 像素 golden。

## 植被复查与性能边界

- 可用 `CHONGMING_GODOT=... uv run python scripts/review_vegetation.py --output output/vegetation-review --samples 12` 生成近景、群落和叶片特写，报告首请求、暖机耗时和同进程空植被对照。当前 macOS M4 / Godot 4.7.2 Compatibility 的三棵树 1024×768 实测暖机约 85--95 ms/帧；首次请求约 0.33 s，包含资源创建及图形初始化。但同期移除全部植被也约 80--90 ms/帧，降低密度或关闭叶片阴影未表现出稳定收益，因此不能将这些墙钟耗时全部归因于树木，也不能据此推断植被规模上限。测量包括场景同步、绘制和像素回读，不是纯 GPU 时间；大场景性能仍需独立验证。
- 这版树木已达到“可辨识的枝干、细枝、独立叶片和可复现实例”验证目标，但仍不是某一树种的精确植物学模型：叶片无外部贴图，枝条规则性较高。乔木和灌木使用硬切换远景代理，草本只保留近景批实例，切换处尚无淡入淡出；真实风场和材质贴图留待后续。逻辑遮挡继续使用圆柱等效轮廓，视觉细节不会改变真值判定规则。
