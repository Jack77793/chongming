# 离散场景时钟与 Godot 按需绘制

本文件记录实现，不增加需求；唯一需求来源是 [虚拟场景需求清单](../../虚拟场景需求清单.md)。

Python 的实验时钟负责曝光时间戳、轨迹、事件序号和真值。墙钟只控制运行节奏和测量处理用时，不改变实验时间。预览默认以 10 Hz 墙钟节拍生产，源端按相机独立的离散计数选择像素请求；有限导出的 `--render-every N` 采用相同机制。

每个逻辑曝光组都输出普通事件、真值和阶段测量。跳过像素的帧有明确 ID 与原因，不生成假图像或检测。预览仅保留每角色最新帧，浏览器轮询不推进时钟，暂停期间不重发事件。

Godot 4.7.2 随场景模块启动，视频开关只控制绘图请求；关闭自动渲染循环，每份不可变快照只绘制一次。Godot 不根据自身 delta 更新物体，未来风、雨、抖动也必须直接从实验时间及固定种子求值。资源随模块停止释放。

保留每步阶段耗时、逻辑/绘图/跳过计数及 p50/p95/最大值。历史 `gpu_ms` 是 Godot 请求内部的更新、绘制、同步与回读墙钟耗时；`gpu_submissions` 是请求数。两者不声称反映 GPU 硬件计数器。

中心工具一次单步完成一个曝光组与中心调用；预览单步到下一可显示帧，无视频时单步一个逻辑组。完整图像算法仍由各业务模块实现，场景提供数据，不伪造检测或中心融合成功。

运行与当前限制见 [虚拟场景运行说明](../虚拟场景预览.md)。
