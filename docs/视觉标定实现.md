# 辅助视觉标定实现

本模块位于 `chongming.calibration`，实现 `ports.device` 中的辅助相机参照识别、姿态估计、历史快照和健康状态管理。OpenCV 只是可替换后端，事件和端口仍使用 `contracts` 中的纯 Python 不可变数据结构。

## 参照物与坐标

首版针对虚拟场景中的横向 A4 棋盘板：7×5 方格，对应 6×4 个内角点。安装配置保存棋盘四个按左上、右上、右下、左下顺序排列的 `SurveyedLandmark`；运行时图像不携带场景真值。内角点的 ENU 坐标由四个外角的双线性插值生成，因此识别器只输出稳定的行列编号和像素坐标。

像素坐标遵循 `ImagePlane` 的左上像素中心约定。识别器接受 `GRAY8`、`RGB8` 和 `BGR8`，尊重行步长，不把 NumPy/OpenCV 对象泄漏到在线契约。检测优先使用经典 `findChessboardCorners` 加 `cornerSubPix`，因为辅助流的固定、光照良好的棋盘在该路径上明显更快；识别失败时回退到 `findChessboardCornersSB` 的归一化和 exhaustive/accuracy 路径。

## 姿态算法

1. 使用辅助相机内参和畸变模型，将 6×4 个像素观测与棋盘 ENU 点配对。
2. 配置包含完整辅助刚体外参时，先固定主相机光心，并用刚性杆臂约束辅助光心随姿态转动，再做三自由度旋转拟合（局部 Gauss-Newton）；这避免近正视平面在亚像素量化误差下把深度/倾角交换成数度的假姿态。没有辅助光心先验时，使用 `solvePnPGeneric(..., SOLVEPNP_IPPE)` 求平面目标的两个位姿候选作为通用后备。
3. 丢弃非有限、点在相机后方、重投影误差超过策略门限，或相对安装基准旋转超过默认 ±1° 的候选。
4. 先用安装先验过滤候选，再以重投影误差解决棋盘行列翻转和其他平面歧义，旋转差作为并列时的排序项。固定主辅旋转外参只用于坐标转换，不在线估计；主相机光心保持安装配置值，辅助相机光心按刚性杆臂随当前辅助姿态变化。

若当前辅助姿态为 `R_enu_from_aux(t)`，安装基准为 `R_enu_from_main,0` 和 `R_aux_from_main,0`，实现的主相机输出为：

```text
R_enu_from_main,t = R_enu_from_aux(t) · R_aux_from_main,0
```

这等价于契约中先求 `R_aux(0)_from_aux(t)` 再转换的写法，避免把修正方向取反。纯旋转模型不吸收整机平移；可配置的 rotation-only parallax 门限用于发现近距离参照造成的视差。

## 历史和健康

`CalibrationHistoryStore` 按站点会话保存不可变 `CalibrationSolution` 和时间排序的 `CalibrationState`。同一 solution ID 的不同内容、非递增参照曝光和跨会话引用都会被拒绝。`snapshot_at()` 同时限制参照曝光中点、解接受时间、状态观测时间和有效区间不晚于主相机曝光中点，所以辅助帧晚到时不会改写过去的主帧语义。

`CalibrationStateMachine` 在识别失败时保留最后可信解并进入 `FROZEN`，超过 `stale_after_ns` 后进入 `STALE`；恢复需要达到 `recovery_success_count` 个连续质量合格样本。没有可信解时只产生诊断，不伪造姿态、光线或零协方差。

## 端侧性能边界

辅助流本来就是低频校准流，`AuxiliaryCalibrationPipeline` 以曝光中点节流，未达到 `update_period_ns` 时复用当前状态，不执行棋盘检测和 PnP。检测阶段只做一次灰度转换，640×480 图像直接处理，不启动 Godot 或完整场景；Godot 仅作为低频形态验证工具。后续 C/Rust 后端可复用同一端口和数据契约，替换 OpenCV 而不改变状态、时间和证据语义。

联合评估结果同时记录识别、姿态估计、状态机、wall-clock 总耗时和进程 CPU 时间。Hannover 640×480、共同相机位置扰动 `(0.005, 0, 0)` m、OpenCV 4.14 的 30 帧实测（热身后）为：识别 P50/P95 `0.966/1.140` ms，姿态拟合 `2.274/3.501` ms，状态机 `0.021/0.035` ms，完整路径 `3.269/4.655` ms（最大 `4.679` ms）；进程 CPU 时间 P50/P95/最大为 `3.349/4.008/4.708` ms。P95 使用最近秩统计，wall-clock 尾部包含操作系统调度抖动；CPU 时间更接近实际算力消耗。原先逐帧使用 `findChessboardCornersSB` 时，识别约 13 ms，完整路径约 16 ms，已经超过 10 ms 预算。SB 仍作为鲁棒回退，因此低对比或异常透视帧的最坏耗时需要单独监控。

姿态拟合的常态路径只尝试检测器给出的棋盘方向；只有该方向不满足安装先验或误差门限时，才尝试其余三种翻转。有限差分中固定的 Rodrigues 增量也会复用，避免每次迭代重复构造。部署侧仍应使用 `update_period_ns` 限制完整检测频率，正常帧复用最近可信解，丢失或质量下降时再重捕获。预算占用可按 `单次总耗时 × 更新频率` 估算：例如 3 ms 的完整检测以 2 Hz 运行，平均仅占 0.6 ms/s；逐帧 30 Hz 则占用约 90 ms/s，并会直接挤压 33 ms 帧预算。
