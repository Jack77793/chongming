## 三组检查

1. 复查完整流与降频证据。按 `manifest.json.stream_mapping` 找到四路 `video/camera-*/` PNG，确认每路有主/辅身份、正确 RGB 尺寸及曝光时刻。`online.jsonl` 只含普通数据，`truth.jsonl` 独立保存对应和真实状态；`timing.jsonl` 每个逻辑组一行，全跳过组为零 GPU submission，不会混入上一组的 GPU 耗时。

   | 最终运行 | 逻辑步骤 / 曝光帧 | PNG / GPU 提交 | 每路 PNG | 射线事件 | 跳过帧 |
   | --- | --- | --- | ---: | ---: | ---: |
   | 完整 | 30 / 120 | 120 / 120 | 30 | 172 | 0 |
   | 每 3 次曝光渲染 | 30 / 120 | 40 / 40 | 10 | 172 | 80 |

   上表是此前 2 秒、15 Hz 短运行的历史计数，不对应当前 24 秒、30 Hz 场景；本地结果不随仓库发布。不要求逐像素人工比较；自动验证检查普通包与真值的确定性，比较时排除新会话 ID 和实际墙钟耗时。PNG 序列是有限视频流的逐帧证据，当前未另封装为 MP4。

2. 编辑 JSON 并重跑。将 `review.json` 另存为 `scenarios/manual-review.json`；把 `duration_s` 改为 `1.0`，再把 `targets` 置为 `[]`。用新目录运行，应得到四路各 30 帧、共 120 帧、目标射线事件为零。校准事件仍可存在。随后可恢复目标、修改轨迹/seed，确认仅编辑语义 JSON 即可定义场景。

   ```sh
   uv run chongming-scene --scenario scenarios/manual-review.json --output results/manual-review-full
   ```

   每次使用尚不存在的输出目录，防止覆盖证据。字段/行为编辑说明见 [预览文档](虚拟场景预览.md)；不要求旧版本兼容。内联高度网格已支持，天气等尚未实现的效果在开始运行前报错。

3. 复查交互与视觉。播放至少一轮，观察运动、遮挡、主辅画面及 RGB 色彩；暂停后切换两站、开关真值叠加，确认视频与标签匹配且时间不推进。单步发布下一组可见帧，中间跳过组只增加逻辑计数；回到起点后仍暂停、显示首帧。顶部“全部逻辑步”和“实际渲染步”分别显示最近 120 个样本的 p50/p95/max，GPU 提交数独立计数。指标跨循环累积，重启不会清零整个进程的监测窗口。

## 验证边界与后续顺序

此前 P2 已通过自动检查。本轮场景整理又检查了全部外部 JSON、非零地形原点与基础高程、山脊遮挡变化、匀速交叉位移；测试覆盖结构、时间、确定性、真值隔离、JSON 修改、失败证据和相机调度，不维护像素 golden。最新检查记录见 [计划](../计划.md)。

4 站基线的暖机串行测量中，GPU 提交从 480 降至 160，平均生成耗时从 57.94 ms 降至 38.66 ms；最大耗时分别为 69.97 / 74.06 ms。该测量只有 60 个逻辑组，已有预览负载未隔离，不能据此宣称单次峰值已经降低。最终有限证据还含冷启动，完整运行最大 134.29 ms、降频最大 61.90 ms；这两次短运行的差异同样不构成稳定上界。

调度使用每相机一个待处理曝光、串行背压和有界预览/统计缓存；尚未做长时间整进程 RSS 验收，也没有操作系统或 GPU 的硬实时保证。图像算法质量评估使用完整渲染，避免把像素跳过当作检测漏帧。

P3 已接入内联高度网格；下一人工复查重点为非零原点地形的视觉位置、遮挡变化和总览一致性。其他环境效应与算法线尚待开发；每项新增效果先明确质量验收，再依据实测尾部耗时决定是否值得进一步优化。
