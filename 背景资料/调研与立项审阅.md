## 1. 结论先行

项目方向在工程上可行，也有研究价值，但当前 `instruction.md` 还不能直接作为实现规格。建议正式立项，前提是先作以下五项修订：

1. 把研究对象准确限定为“运动小型空中目标的检测、三维定位与跟踪”。现方案没有可靠的类别识别能力，不应把“识别无人机”写成已解决目标。
2. 把“传统方法更远、更准、几乎不漏检、必然比深度学习便宜”等结论改为待检验假设；所有比较必须在相同摄像机、数据、功耗、带宽和误警约束下完成。
3. 保留“端侧稀疏观测、中心端粗到细几何解算”的主架构，但补上时间同步、不确定度、跨相机数据关联、三维跟踪和标定漂移监测。
4. 不复制 Consistently Inconsistent 上游代码。其代码是概念样例，且许可证含额外用途/主体限制，不是标准 Apache-2.0；采用洁净重写更安全。
5. 把学术贡献定位在“资源受限条件下的端云协同与成本—性能边界”，而不是体素投票或多摄像机背景减除本身。Wang et al.（2023）和 Law（2026）已覆盖非常接近的基本架构。

建议的研究定位是：

> 面向低成本被动光学摄像网络的资源感知型稀疏视线事件三维小型空中目标定位：以带时间与不确定度的边缘观测、按摄像机去相关的分层概率体素、鲁棒三角化，以及仿真到真实的成本—性能评估为核心。

如果三个月内只能完成虚拟世界中的体素投票复现，成果主要是工程演示；如果能完成低价真实节点、同步与标定误差实验、公开评估协议或数据集，则具备更明确的系统研究价值。

### 4.3 重要缺陷和经验

1. `extractor.py` 使用 `CHAIN_APPROX_NONE` 后以 `len(contour)` 作为面积；它实际是轮廓点数，不是像素面积或 `contourArea`。

3. `FramePacket` 默认元数据只做浅拷贝，嵌套值可能跨包污染。
4. 标定加载器没有接入视频主链，位姿标定工具未实现，旋转约定未最终统一。
5. 文档同时存在“帧差 + Mask”和“时域中值背景”两代描述，参数默认值也互相矛盾。
6. 仿真只支持单目标、直线/悬停和非常有限的相机布局；无法检验多目标交叉、遮挡、数据关联、畸变、时钟漂移、延迟丢包与真实三维解算。
7. 部分录像与 GT 帧数/修改时间不匹配，不能直接作为正式回归数据。

### 4.4 旧“最小二乘”并不是最小二乘

历史提交 `1029a72b` 中的 `_refine_with_ls`：

- 枚举一个候选簇中的全部射线对；
- 对每一对斜线求最近两点的中点；
- 对所有 pair midpoint 做算术平均。

这只是 `O(k²)` 的射线对中点平均，不是联合多射线最小二乘，也没有相机去重、角度权重、协方差或鲁棒损失。后来提交 `a7919182` 因复杂度和收益问题删除它，因此旧原型不能作为“最小二乘无收益”的证据。

对单位方向 `d_i`、射线原点 `o_i` 和权重 `w_i`，真正的点到直线加权最小二乘可写为：

```text
A = Σ w_i (I - d_i d_iᵀ)
b = Σ w_i (I - d_i d_iᵀ) o_i
求解 A x = b
```

构造 `A/b` 对射线数 `k` 是 `O(k)`；3×3 求解是常数规模。实际方案还应报告 `A` 的条件数，用交会角门控，并采用 Huber/L1/IRLS 或 RANSAC 抑制错误关联。

### 4.5 旧时序/协议不可继承

旧 `ray_buffer.py` 使用服务器到达时间保留最近 100ms，窗口不消费；`brain_main.py` 每约 33ms 求解，并用“射线数量是否变化”去重。它会：

- 在重叠窗口中重复使用同一条射线；
- 把运动目标不同时刻的位置混在一个体素或精化问题中；
- 受网络乱序和时钟差影响；
- 在“新旧射线数量刚好相等”时漏掉内容变化。

按相机 OR-mask 每体素最多一票只能修复重复计票语义，不能修复时间几何错误。新系统必须以采集事件时间、单调序列号、时钟质量和 bounded lateness 为基础推进窗口。

### 5.2 两条不同的实验路径

低空/多相机路径 `ray_voxel.cpp`：

1. 按相机和 frame index 读取图像；无采集时间同步。
2. 相邻灰度帧逐像素绝对差，阈值为 2；图像还被人为加入均匀随机噪声。
3. 每个变化像素通过单一 FOV、图像中心主点和 Euler 角生成射线。
4. AABB + 3D DDA 遍历体素，把差值亮度累加到沿线所有体素。
5. 写出 `500³` 的 float32 稠密网格，约 500MB，再由另一脚本显示。

天文/FITS 路径 `spacevoxelviewer.py + process_image.cpp`：

- 使用 FITS、Earth barycentric position、RA/Dec/ICRS、天球纹理和约 41.7AU 尺度；
- 使用 `400³` float64 网格，基础内存约 512MB，每条 ray 固定采样 20,000 步；
- 当前调用关闭背景减除；它不是低空帧差主路径。

第二条路径不能直接迁移到低空无人机，只可借鉴“把稳定背景映射到世界/角坐标”和用 AABB 限定计算区域。

### 5.3 与 `instruction.md` 不一致的关键事实

- 空间解算不是 GPU/CUDA。`ray_voxel.cpp` 是串行 CPU；`process_image.cpp` 使用 OpenMP CPU；CUDA 只在 Blender/Cycles 合成渲染中出现。GPU 解算仍是开放的 [issue #5](https://github.com/ConsistentlyInconsistentYT/Pixeltovoxelprojector/issues/5)。
- 上游没有云端/边缘通信层，也没有“接收视频流”的实现。
- 体素得分没有按独立摄像机去重，同一相机的邻近像素和多帧可自行堆出热点。
- 元数据只有位置、Euler、单 FOV；缺少内参矩阵、畸变、协方差、曝光与完整时间信息。
- 生成器、解算器和 viewer 的网格中心/轴解释不一致，不能把现有图像当作几何正确性证明。

### 5.4 正确的复杂度描述

设：

- `F`：比较帧数；
- `P=H×W`：每帧像素数；
- `K`：全部变化像素产生的射线数；
- `L`：一条射线穿过的体素数；
- `V=N³`：稠密网格大小。

则上游流程约为：

```text
帧差       O(FP)
体素投射   O(KL)
网格清零/输出/全扫 O(V)
内存       O(V)
```

若有 `C` 台相机、每台 `n` 条候选射线，总射线 `R=Cn`，显式全对求交是 `O(R²)=O(C²n²)`；DDA 投票是 `O(RL)+O(V_active)`，不是无条件的 `O(Cn)`。

### 5.5 可借鉴与不继承

可借鉴：候选像素/组件到单位方向的接口、ray–AABB、DDA、合成数据完整真值、粗体素召回后局部解析几何。

不继承：硬编码 `500³` 网格、原始差值无限累加、同相机重复计票、每像素动态分配完整 ray path、单 FOV/Euler 假标定、无 timestamp、全网格 dump、FITS 主链、轴约定和现有许可证代码。

## 6. 学术调研与项目价值

### 6.1 最接近的先行工作

1. Wang, Williams & Wong, 2023，[Probability map based aerial target detection and localisation using networked cameras](https://doi.org/10.2514/6.2023-2580)。摘要明确使用相距较远的商用 webcam、每站 SBC 背景减除、中央 probability map/trilateration、室内小无人机试验和机场 ADS-B 对照。它与本项目基本系统架构高度重合。
2. Law, 2026，[Volumetric motion detection for multi-drone swarm engagement](https://doi.org/10.1177/15485129251415238)。摘要明确使用 Bayesian occupancy grids、space carving、multi-view triangulation、CPU 并行和 8-camera visible array，并以 50 个 Monte Carlo 场景评估。它与体素/低算力路径高度接近。

因此，“多摄像头 + 背景减除 + 中央概率图/体素定位”本身的新颖性很弱。

更有希望的组合贡献：

2. 按独立摄像机支持度去相关的概率体素，以及事件风暴下的有界复杂度设计。
3. 粗体素门控到不确定性感知的鲁棒三角化，并显式处理几何退化。
4. 带宽、功耗、误警、召回、三维误差与维护成本的联合 Pareto 曲线。
5. 标定漂移、时钟偏差、网络乱序、动态背景和相机布局的系统消融。

## 7. 推荐的系统边界

```text
真实/渲染主视频 ─┐
真实/渲染辅助视频 ──> 端侧传统 CV + 参照校准 + 世界射线生成 ──> 稀疏世界射线事件 ───┐
直接真值模拟 ───────────────────────────────────────────> 稀疏世界射线事件 ───┤
                                                                                 v
设备注册/校准状态审计 ───────────────> 时间对齐/事件水位 ─> 跨相机关联
                                                        |
                                                        v
                      按相机去重的概率粗体素/稀疏占据
                                                        |
                                                        v
                         鲁棒加权三角化 ─> 3D 轨迹滤波
                                                        |
                                                        v
                              回显、记录、评估与健康监测
```

端侧职责：主/辅助视频输入、视频质量检测、必要的稳像/背景建模、候选组件、单相机短轨迹、辅助参照识别、运行时校准状态更新、世界射线生成、置信度估计、事件打包、可选触发式图像片段留存。

中心端职责：设备注册与配置/校准状态审计、事件时间对齐、跨相机关联、粗体素门控、精确三角化、3D 多目标跟踪、可视化与可复现记录。中心端不再从像素观测生成世界射线。

世界射线是正式融合接口；为便于调试和误差分析，设备端可选择附带原始像素/归一化视线，但中心端不应依赖它重新推导另一套姿态。对固定节点，推荐发送：

```text
schema_version, session_id, node_id, camera_id
sequence_number, capture_timestamp, clock_domain, clock_uncertainty
station_id, world_frame_id, config_version
calibration_state_version, calibration_valid_from/to
world_ray_origin, world_ray_direction
ray_covariance or angular/origin uncertainty, confidence
optional: pixel_centroid or normalized_bearing, component area/bbox
local_track_id, local_velocity, track_state
payload_length, checksum
```

固定站点坐标、参照世界坐标和相机外参由设备端人工配置并按版本保存；中心端可保存同源副本或摘要用于审计，但不逐帧下发。设备端生成的 `world_ray_origin/direction` 及其不确定度必须与主相机曝光时刻和校准状态有效区间对应。事件风暴时应有速率上限、汇总模式和降级标记，不能静默丢弃整个周期。

## 8. 核心研究问题与假设

### RQ1：端侧传统 CV 是否在资源约束下形成更好的工作点？

H1：在固定节点功耗、处理器和误警预算下，完整传统管线相对纯帧差显著降低每小时误警，同时保持可接受召回。
对照：frame diff、MOG2、ViBe、当前时域中值、轻量 MobileNet/tiny-YOLO。

### RQ2：稀疏观测是否真正降低系统成本？

H2：在同等检测/定位质量下，稀疏事件相对 H.264/H.265 视频、关键帧/ROI 传输降低 p95 带宽、中心解码成本或总能耗。
必须把事件风暴、协议头、重传、时钟同步、端侧 CPU 和触发式证据帧计入。

### RQ3：粗体素 + 鲁棒精化是否优于单独方法？

H3：按摄像机去重的分层概率体素能在错误候选存在时提供高召回门控；其后加权/鲁棒三角化显著降低体素量化误差，并优于 pairwise midpoint、固定细网格和无权 LS。

### RQ4：标定、同步和布站误差的可接受边界是什么？

固定双目近似下，深度误差满足：

```text
σ_Z ≈ Z² σ_d / (f B)
```

目标速度 `v`、时间偏差 `Δt` 会带来约 `vΔt` 的跨相机位置不一致。例如 20m/s 与 50ms 已对应约 1m。姿态误差 `δθ` 在距离 `Z` 处形成约 `Zδθ` 的横向误差。三者都必须被注入仿真并在真实部署中测量。

### RQ5：仿真结论能否迁移到真实世界？

H5：在相同目标角尺寸、对比度、运动模糊和标定噪声分层下，仿真与真实数据的性能排序一致；若只在仿真成立，则不能作为系统有效性结论。

## 9. 实验设计

### 9.1 三层解耦验证

1. **GT ray 层**：直接由已知相机与 3D 目标产生无误差事件，验证坐标系、DDA、关联、LS 和 tracker。
2. **含噪 ray 层**：注入像素噪声、置信度、假射线、漏射线、姿态漂移、时钟偏差、乱序和丢包，验证鲁棒性及误差传播。
3. **视频检测 ray 层**：渲染/真实视频经过端侧 CV，再进入完全相同的中心端接口，隔离 2D 检测误差与 3D 几何误差。

### 9.2 基线候选（早期建议，非本期必做清单）

端侧：纯帧差、MOG2、ViBe、时域中值/完整传统管线、至少一个可部署轻量网络。
空间：直接 pairwise closest point、RANSAC、无权联合 LS、加权/鲁棒 LS 或 LOSTU、固定体素、分层概率体素、Wang 风格概率图。
通信：连续压缩视频、ROI/关键帧、稀疏观测。
系统：Consistently Inconsistent 思路的洁净复现；不复制其代码。

### 9.3 指标

| 层 | 指标 |
|---|---|
| 二维检测 | precision、recall、F1/AP、每摄像机小时误警数、最长连续漏检、确认延迟、ID switches、质心/方位误差 |
| 三维定位 | RMSE/MAE/P95、水平/高度/深度误差、1/5/10m 命中率、置信区间覆盖率、轨迹连续性 |
| 系统 | p50/p95 端到端延迟、FPS、CPU/RAM、W、J/frame、bytes/event、平均/p95 带宽、丢包恢复 |
| 成本 | BOM、安装时间、标定时间、重标定频率、维护工时、中心计算需求 |
| 距离 | range-at-first-detection，同时报告目标像素尺寸、镜头、对比度、天气和误警阈值 |

所有检测指标至少按目标像素尺寸（如 `<8`、`8–16`、`>16`）、距离、角速度、背景、光照、天气和遮挡分层。只报告平均值会掩盖小目标失效区间。

### 9.4 数据

- 公共二维数据：Drone-vs-Bird、DUT Anti-UAV；SynDroneVision 用于考察仿真域。
- 本地程序化/游戏引擎仿真：必须扩展到多目标、交叉/遮挡、不同内参/外参、目标尺度/对比度、滚动快门、压缩、天气和网络错误。
- 真实数据：至少完成同步双/三相机小规模外场，目标携带可作为三维真值的 GNSS/RTK 或高可信替代测量。
- 目前没有发现同时覆盖“多地面相机、同步、标定、小无人机三维真值”的直接开放数据集；建立并发布小型数据集可能成为贡献。

## 11. 建议预注册的否证条件

以下结果应被接受为假设不成立，而不是无限调参：

1. 在同数据、同摄像机和同带宽约束下，完整传统后处理没有显著降低误警，或召回损失抵消收益。
2. 稀疏事件加上边缘计算、同步、重传和证据帧后，带宽/能耗不优于压缩视频或 ROI 基线。
3. 粗体素 + 鲁棒精化相对概率图、直接鲁棒三角化或固定体素没有改善三维 P95/算力 Pareto。
4. 1–2 像素误差、现实姿态漂移或可负担的时钟误差就使三维误差超过业务阈值。
5. 动态云、树、水面、鸟虫或相机抖动下，误警率仍不可运营。
6. 仿真中有效，但真实外场性能排序或绝对指标严重崩溃。
7. 系统只有在极小交会区域、理想基线或频繁人工重标定下工作。

具体数值阈值需由目标使用场景和后续讨论决定；在不知道保护范围、目标速度/尺寸、允许误警和定位容差之前，不应凭空设定“1km、5m、95%”等成功数字。
